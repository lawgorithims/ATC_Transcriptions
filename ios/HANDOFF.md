# Obelisk — Session Handoff

Pick up the **Obelisk** iOS app (on-device ATC transcription) in a fresh session without losing
context. Pairs with `RECOVERY.md` (rebuild the ship box) and the Claude **memory notes** (which hold
the secret IDs and box details — this repo is **PUBLIC**, so nothing secret lives here).

> ⚠️ **Public repo.** Do NOT commit secrets, App Store Connect key IDs, the `.p8`, or the build-box
> host/IP. Those live in the memory notes named below and on the build box.

## 1. What this is

- **Obelisk** — universal iPhone/iPad SwiftUI app, fully on-device ATC radio transcription.
  Fine-tuned Whisper via **WhisperKit** (CoreML/ANE) + a two-tier corrector (deterministic + an
  optional CPU llama.cpp / Apple-Foundation LLM) + RAG context. Sources: internet LiveATC feed,
  device mic, USB audio, replay demo.
- Repo: **`lawgorithims/ATC_Transcriptions`** (local dir is `ATC_Transcribe`). Work on **`main`**.
  All app code is under `ios/ATCTranscribe/`. The Xcode project is generated by **xcodegen** from
  `ios/project.yml` (no checked-in `.xcodeproj`).
- App Store Connect app **Obelisk**, bundle `com.flycommsight.atctranscribe`. **Builds 1–8 shipped
  to TestFlight on 2026-06-27**; current `main` is the build-8 state.

## 3. Build / test / ship loop (the actual cadence used all session)

The build box (a headless Scaleway M4 Mac, `User m1`) has Xcode, the models, and the vendored
`llama.xcframework`. Local edits on Windows; **nothing compiles on Windows**.

**Iterate (sync changed files → build/test):**
```bash
# from ios/ on the Windows box, tar the files you changed to the M4 (no --delete; never touch
# Resources/Models or Vendor):
tar czf - ATCTranscribe/UI/Foo.swift ... | ssh m1@<host> 'cd ~/ATC_Transcribe/ios && tar xzf -'
# on the M4: regen + test against the BOOTED simulator (id from `xcrun simctl list devices booted`):
export PATH="$HOME/.xcodegen/xcodegen/bin:$PATH"
xcodegen generate
xcodebuild -project ATCTranscribe.xcodeproj -scheme ATCTranscribe \
  -destination 'platform=iOS Simulator,id=<BOOTED_SIM_ID>' \
  -derivedDataPath /tmp/dd-obelisk CODE_SIGNING_ALLOWED=NO test
```
- Adding a **new .swift file** requires `xcodegen generate` before `xcodebuild` (globs at gen time).
- `git reset --hard origin/main` on the M4 is the safe way to put it on an exact commit before
  shipping (Resources/Models + Vendor are untracked/ignored and survive the reset).

**Ship to TestFlight (outward-facing — only when the user asks):**
```bash
# on the M4, in ios/, with the ASC env from the memory note + the NEXT build number:
ASC_KEY_ID=... ASC_ISSUER_ID=... ASC_KEY_PATH=/Users/m1/AuthKey_*.p8 TEAM_ID=... \
BUILD_NUMBER=9 bash Tools/ship_testflight.sh
```
`ship_testflight.sh` is the **headless-correct** recipe (archive UNSIGNED → sign-for-distribution at
export). `Tools/testflight.sh` does NOT work over SSH. **LEAN=1** (default) ships model-less; the app
downloads models on first launch from HuggingFace (`SingularityUS/atc-whisperkit`).

**Version gotcha (fixed build 3+):** `project.yml` info binds `CFBundleVersion=$(CURRENT_PROJECT_VERSION)`
and `CFBundleShortVersionString=$(MARKETING_VERSION)` (=1.0). Without that, xcodegen baked a literal
`1` and uploads collided. Builds ship as `1.0 (N)`.

## 4. Working practices that worked well

- **Cadence:** edit → sync → `xcodebuild test` on M4 → fix → commit to `main` → `reset --hard` M4 →
  `ship_testflight.sh BUILD_NUMBER=N`. Each batch = one build.
- **Adversarial review before every ship.** Run a `Workflow` that fans reviewers across dimensions
  (concurrency, SwiftUI, DSP, regressions) then adversarially verifies each finding against the code.
  This caught real HIGH bugs every batch (audio-session leaks, an AVAudioEngine re-attach crash, a
  mic data race, a hallucination-filter resurrection, a per-segment decode blowup). **Keep doing it.**
- **Tests:** unit + XCUITest on the Simulator. `test1_onboardingGateAndSkip` XCTSkips when a model is
  bundled (the gate only shows on lean builds) — that 1 skip is expected. The **neural path** (real
  ANE) is validated by the macOS `ATCKitProbe` (`Tools/probe.sh`), NOT the Simulator (no ANE there).

## 5. Architecture map (key files)

- `Engine/LivePipeline.swift` — actor: source chunks → VAD → **diarize** → preprocess → transcribe →
  correct → `TranscriptRecord`; runtime setters (`setCorrector/LLM/Gate/Squelch/Diarization`).
- `Engine/TranscriptionSession.swift` — @MainActor ObservableObject wrapper; owns audio-session
  teardown on stop/natural-end; `inputLevel`.
- `UI/AppModel.swift` — the view-model (sources, model switching, standby, squelch, diarization,
  showDebug, widgets, onboarding gate). `start()/beginCapture()` (mic permission + session activate).
- `Audio/` — `AudioSource` (mic/USB/replay), `StreamAudioSource` (LiveATC MP3 decode),
  `AudioSessionManager`, `AudioMonitor` (live-feed speaker monitor), `VADSegmenter`, **`Diarizer`**.
- `Core/` — `ATCCorrector` (deterministic + **HallucinationFilter** + chain), `RepetitionCollapse`,
  `LocalLLMCorrector`/`FoundationModelsCorrector`, `ConfidenceGate`, RAG (`ATCKnowledge*`).
- `UI/` — `ConsoleView` (top bar, controls, input meter, standby banner, `SquelchControls`),
  `TranscriptView` (rows + speaker chips + amber correction highlight), `SidebarView` (customizable
  widgets incl. `DiagnosticsCard`), `SettingsSheet`, `Theme` (blue accent), `DeviceLoad` (CPU/thermal).
- `Download/` — `ModelCatalog`, `ModelDownloadManager`, `OnboardingDownloadView` (first-run gate).

## 7. OPEN LOOPS — what a fresh session should pick up

**Device-only validations the user still needs to confirm (can't be tested headless):**
1. **Microphone actually captures** on device (build 5 created the engine after the session is
   active + added a no-audio watchdog). If still silent, the watchdog message + the exact on-screen
   error are the clues.
2. **Live-feed speaker monitor** — audio comes out the speakers (build 5).
3. **Battery** while idle/backgrounded (the session-leak fixes + standby).
4. **Diarization quality** on a real feed — does it put ATC/aircraft on separate lines, or
   over-split / mislabel? Thresholds in `Diarizer.swift` are easy to tune; toggle in Settings → Speakers.

**Known limits / candidate next work:**
- **Diarization can't separate simultaneous talkers (overtalk).** The heuristic v1 splits on PTT
  gaps + acoustic clustering. The "very robust" upgrade = a dedicated **speaker-embedding CoreML
  model** (project on the scale of the Whisper conversion: pick/convert a model, host on HF, wire a
  download + per-segment embedding + clustering). Scope it if the user wants overtalk handling.
- HallucinationFilter blocklist is just `["no call of"]` — extend `Diarizer`… (actually
  `Core/ATCCorrector.swift` `HallucinationFilter.phrases`) as new Whisper phantom phrases surface.
- `noisereduce` preprocessing stage from the Python is still not ported (see `AudioPreprocessor`).

**Thunderstorm alert (`Core/ConvectiveAlert.swift`) — what it now reads, and what is still open.**

The alert is **source-agnostic**: it consumes `ConvectiveCell`s, and four products supply them, because
no one product answers the whole question. `ConvectiveCellMerge` folds them into one list — identity to
the highest-ranked source (the name a controller would use), every number to whichever source has the
conservative one.

| source | polygon | tops | motion | file |
|---|---|---|---|---|
| Convective SIGMET (AWC) | area | stated | stated | `Hazards/ConvectiveSigmetService.swift` |
| Center Weather Advisory | smaller area | **text only** | **text only** | `Hazards/CWAParser.swift` |
| NWS Severe Tstm Warning | one storm | **none** | stated, recent | `Hazards/SevereWarningParser.swift` |
| MRMS echo tops | one storm, measured | **measured** | derived | `Hazards/MRMSEchoTopService.swift` |

MRMS closes the gap the bulletins leave: a Convective SIGMET needs ~40% coverage, a line, or a severe
cell, so an isolated ordinary thunderstorm can be reported by nobody. Verified end to end on 2026-11-04
against a 59,055 ft echo top at 26.87/−97.58 that **no** Convective SIGMET covered.

Three things found by measurement that a future session should not have to rediscover:

1. **MRMS is small.** The CONUS `EchoTop_30` grid is **364 KB** gzipped (an earlier note here ruled MRMS
   out on size and was wrong by an order of magnitude). Discovery is a **1.4 KB** S3 listing using
   `start-after` on the NOAA Open Data mirror, because keys sort chronologically.
2. **The only format blocker was GRIB2 template 5.41** (PNG payload). `PNGGrayRows` decodes it
   **row by row** rather than through ImageIO, because the CONUS bitmap is 49 MB and the window needs
   ~0.5 MB of it; the decode stops at the southern edge of the window. Measured 96 ms for a 4° box.
3. **Centroid tracking of threshold blobs does NOT give storm motion.** Tried first; against two real
   frames inside Convective SIGMET 7C (bulletin: MOV FROM 270 at 20 kt) it returned FROM 031 @ 51 kt,
   FROM 044 @ 66 kt and FROM 232 @ 59 kt — scattered through all four quadrants, because a 23 NM blob's
   centroid wanders further than the storm translates. Replaced by whole-field cross-correlation
   (`RadarCellFinder.fieldMotion`), which agreed with four independent bulletins to within 13°.

**OPEN — in rough value order:**

- **Derived motion reads 20–25% SLOW**, every time, measured against four bulletins. It is structural:
  maximising overlap anchors on the persistent core while only the flanks translate. Currently paid for
  with a wider drift allowance (`ConvectiveAlert.radarDriftErrorFraction = 0.40`) rather than a fudge
  factor on the speed. A proper fix is per-cell TREC with sub-pixel peak interpolation.
- ~~**Overflight clearance uses the AIM's 5,000 ft FLOOR**~~ — DONE (2026-11-04). The full rule is
  applied: `ConvectiveAlert.requiredClearanceFt` takes the greater of the 5,000 ft floor and 100 ft per
  kt of wind at the cell's own top, sampled from the held GFS field by `WindFieldSet.windAt`. Two things
  to know before changing it. (a) **The wind may only raise the bar** — nil, calm, stale or
  outside-the-box all return the floor, which is the behaviour the alert had before; every absent-wind
  path can therefore stay a plain `nil`. (b) **The fetch is no longer tied to the wind overlay**:
  `AppModel.stormAlertNeedsWind` enables `WindAloftService` whenever a storm alert has a live cell,
  because `showWindAloft` defaults OFF and the rule would otherwise be dead on a fresh install. Fetching
  does not draw — the particle layer is gated separately. Measured live on 2026-11-04 12z+7h over
  22–42N/113–78W: of the six live Convective SIGMETs, every top sat in 28–46 kt, so the rule asked for
  the floor at all six — but 41% of the box at 31,000 ft and 51% at 39,000 ft were over 50 kt (peaks of
  114 and 118 kt, which ask for ~11,500 ft), so it binds often, just not wherever storms happen to be.
  What is still missing: **nothing tells the pilot the rule is running on an OLD wind** — `freshFieldSet`
  refuses a stale run and the banner then silently reverts to the floor.
- **The layers panel is ~2,000 pt of prose and has no scroll affordance.** Every live layer carries an
  explanatory note while it is ON, so on a 13-inch iPad the overlays column is about two and a half
  screenfuls and the clipped edge looks like the end of the list. The popover cap has been raised twice
  (460 → 860 → 1,100) chasing it, and each raise was forced by a UI test finding a row that had dropped
  below the fold — the second time as three silently dropped taps that read like a dead binding. The cap
  is now "as much as the device will give"; the remaining fix is editorial, not geometric.
- **No map overlay.** The banner names the cell but nothing draws its polygon, so the pilot cannot see
  WHERE it is without going to the WX tab. `TFRMapLayer` is the pattern, on both map engines. This now
  matters more than it did: a radar-derived cell has no name to look up, so the outline is the only way
  to see what it is talking about.
- **MESH (hail) is 30 KB on the same cadence** and would give radar cells a real severity instead of
  nil. Cheap, not wired.
- **CONUS only.** Convective SIGMETs are CONUS + coastal waters; the MRMS CONUS grid likewise. MRMS also
  publishes ALASKA and CARIB domains, which the decoder would handle unchanged — only the product paths
  and a domain choice are missing.
- **No FIS-B.** The Stratux integration is GPS/traffic only. FIS-B would give NEXRAD and lightning with
  no internet at all, which matters when cellular dies at altitude. Not investigated beyond confirming
  the current link does not carry it.
